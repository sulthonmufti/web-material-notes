Status & Log

Memantau Kondisi Sekarang dan Menelusuri Jejak Masa Lalu

1. git status: Pemeriksaan Kesehatan Proyek +

git status memberi tahu Anda file mana yang telah diubah, file mana yang sudah siap di-commit, dan file mana yang belum dilacak oleh Git.

📖 Istilah: Untracked vs Tracked
  • Untracked: File baru yang belum pernah dikenalkan ke Git (biasanya muncul warna merah).
  • Modified: File lama yang sudah ada di Git tapi isinya berubah (warna merah).
  • Staged: File yang sudah di-git add dan siap dibungkus (warna hijau).
🏢 Kasus Real: Menghindari Commit "Nyasar"

Sebelum melakukan commit, developer selalu menjalankan git status untuk memastikan tidak ada file rahasia (seperti .env atau password) yang tidak sengaja masuk ke area staging.

2. git log: Mesin Waktu Proyek +

git log menampilkan daftar semua commit yang pernah dilakukan dalam proyek ini secara urut (dari yang terbaru ke terlama).

# Melihat riwayat lengkap
git log

# Melihat riwayat ringkas (satu baris per commit)
git log --oneline
📖 Isi dari sebuah Log:

Setiap entri log berisi: Commit Hash (ID unik), Author (siapa yang mengerjakan), Date (kapan dikerjakan), dan Message (apa yang dikerjakan).

3. Filter & Pencarian Log Profesional +

Dalam proyek dengan ribuan commit, Anda tidak mungkin membaca semuanya satu per satu. Gunakan filter ini:

# Melihat 3 commit terakhir saja
git log -n 3

# Mencari commit berdasarkan penulis tertentu
git log --author="Budi"

# Melihat log dalam bentuk grafik cabang
git log --graph --oneline --all
🏢 Kasus Real: Audit Perubahan

Saat terjadi error di produksi, tim senior sering menggunakan git log -S "kode_yang_error" untuk mencari tahu kapan tepatnya baris kode tersebut pertama kali muncul dan siapa yang menulisnya.
