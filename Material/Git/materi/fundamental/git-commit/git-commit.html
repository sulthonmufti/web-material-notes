Git Commit

Mengunci Snapshot dan Menciptakan Garis Waktu Proyek

1. Apa itu git-commit? +

git commit adalah perintah untuk menyimpan perubahan yang ada di Staging Area ke dalam database lokal Git sebagai sebuah Snapshot permanen.

📖 Analogi: Checkpoint Game

Bayangkan Anda sedang bermain game RPG. Sebelum melawan bos yang sulit, Anda melakukan "Save Game". Jika Anda kalah (kode error), Anda bisa kembali ke titik save tersebut. Commit adalah save point bagi kode Anda.

🏢 Kasus Real: Menelusuri Bug

Jika aplikasi tiba-tiba error hari ini, developer bisa melihat riwayat commit untuk mencari tahu baris kode mana yang diubah kemarin dan siapa yang mengubahnya. Tanpa commit yang rutin, Anda akan tersesat di tumpukan kode Anda sendiri.

2. Cara Melakukan Commit +

Syarat utama melakukan commit adalah file harus sudah di-add (berwarna hijau di git status).

# Cara standar (pesan satu baris)
git commit -m "tambah fitur navigasi"

# Cara cepat (add + commit sekaligus untuk file yang sudah terlacak)
git commit -am "perbaiki layout footer"

# Mengubah pesan commit terakhir (jika ada typo)
git commit --amend -m "pesan yang benar"

🛠️ Simulasi Riwayat Commit

Tulis pesan commit dan tekan Enter untuk melihatnya masuk ke sejarah (log):

a1b2c3d initial commit
3. Standar Industri: Conventional Commits +

Di perusahaan besar, pesan commit tidak boleh asal-asalan. Kita menggunakan format type: description.

Tipe Kegunaan
feat: Menambahkan fitur baru.
fix: Memperbaiki bug.
docs: Perubahan dokumentasi (ReadMe, dsb).
refactor: Mengubah struktur kode tanpa mengubah fungsi.
✅ Contoh Bagus: feat: tambah validasi form login
❌ Contoh Buruk: update, fix bug, bismillah kelar
4. Apa yang Ada di Dalam Commit? +

Setiap commit memiliki identitas unik yang disebut SHA-1 Hash.

  • Hash (ID): Kode 40 karakter unik (misal: 4f2a7b...).
  • Author: Nama & Email (dari git config).
  • Date: Kapan commit tersebut dibuat.
  • Parent: Referensi ke commit sebelumnya (sehingga membentuk rantai sejarah).
