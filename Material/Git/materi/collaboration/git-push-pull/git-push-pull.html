Push & Pull

Sinkronisasi Kode: Mengirim dan Menjemput Perubahan

1. git push: Mengunggah Karya +

git push adalah perintah untuk mengirim commit lokal Anda ke repositori remote (seperti GitHub). Ini adalah cara Anda membagikan hasil kerja kepada tim.

📖 Istilah: Upstream (-u)

Saat pertama kali push, kita sering menggunakan -u (upstream). Ini seperti "mengingat" pasangan branch lokal dan remote, sehingga kedepannya Anda cukup mengetik git push saja.

# Push pertama kali (setup upstream)
git push -u origin main

# Push selanjutnya
git push
🏢 Kasus Real: Deployment Otomatis

Di industri modern, melakukan git push ke branch tertentu (misal: production) seringkali memicu sistem CI/CD yang secara otomatis mengunggah kode Anda ke server aplikasi (Live).

2. git pull: Mengambil Update Tim +

git pull digunakan untuk mengambil perubahan terbaru dari server remote dan langsung menggabungkannya (merge) ke dalam kode lokal Anda.

🔍 Bedanya dengan git fetch?
  • Fetch: Hanya melihat/mengunduh info tanpa mengubah kode Anda.
  • Pull: Fetch + Merge (Langsung memperbarui file Anda).
git pull origin main
3. Konflik & "Pull Before Push" +

Kenapa Git terkadang menolak push Anda? Biasanya karena ada teman tim yang sudah mengirim kode lebih dulu, dan laptop Anda belum mengetahuinya.

⚠️ Aturan Emas: Pull Before Push

Selalu lakukan git pull sebelum memulai kerja atau sebelum melakukan push. Ini meminimalisir terjadinya Merge Conflict (bentrokan kode).

📖 Apa itu Merge Conflict?

Kondisi di mana dua orang mengubah baris kode yang sama di file yang sama. Git akan bingung mana yang benar dan meminta Anda untuk memilih manual.
