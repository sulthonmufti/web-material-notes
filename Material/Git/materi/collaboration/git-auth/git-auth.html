Git Authentication

Mengamankan Akses dan Identitas Developer

1. HTTPS & Personal Access Token (PAT) +

Saat menggunakan URL HTTPS, Git akan meminta username dan password. Namun, sejak 2021, GitHub tidak menerima password akun. Anda harus menggunakan PAT.

📖 Istilah: Personal Access Token (PAT)

PAT adalah pengganti password yang bisa diatur masa berlakunya dan hak aksesnya (misal: hanya bisa baca kode, tidak bisa hapus repo).

🏢 Kasus Real: Keamanan Bertingkat

Jika laptop Anda hilang, Anda cukup menghapus PAT dari akun GitHub melalui browser. Password utama Anda tetap aman, dan akses dari laptop tersebut otomatis terputus.

2. SSH: Autentikasi Tanpa Password +

SSH (Secure Shell) adalah metode paling populer di kalangan pro-developer. Anda tidak perlu mengetik token setiap kali push/pull.

📖 Konsep: Key Pair
  • Private Key: Tetap di laptop Anda (rahasia).
  • Public Key: Diunggah ke server GitHub/GitLab.

Keduanya bekerja seperti gembok dan kunci fisik.

$
Contoh:
# Membuat SSH Key baru
ssh-keygen -t ed25519 -C "email@kamu.com"
# Melihat isi Public Key
cat ~/.ssh/id_ed25519.pub
3. Git Credential Manager (GCM) +

Bosan dimintai login terus menerus? Git memiliki fitur untuk mengingat kredensial Anda dengan aman di sistem operasi.

$
Contoh:
# Mengaktifkan memori login di Windows/Mac
git config --global credential.helper manager
🏢 Kasus Real: Multi-Account

Developer sering memiliki akun kantor dan akun pribadi. GCM membantu mengelola banyak token sehingga Anda tidak tertukar saat mengirim kode ke server kantor.
