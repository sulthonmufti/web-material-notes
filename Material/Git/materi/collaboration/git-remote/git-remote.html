git remote

Manajemen Koneksi Antar Repositori

1. Menghubungkan Lokal ke Awan (git remote add) +

Gunakan perintah ini saat Anda memiliki proyek di komputer dan ingin mengunggahnya ke repositori kosong di GitHub/GitLab.

git remote add origin https://github.com/user/proyek.git
📖 Istilah: Upstream

Dalam kolaborasi tim, seringkali ada istilah Upstream. Ini biasanya merujuk pada repositori pusat (asli) milik organisasi, sementara Origin merujuk pada hasil 'Fork' milik Anda sendiri.

🏢 Kasus Real: Inisialisasi Repositori Perusahaan

Setelah tim DevOps membuatkan slot repositori kosong di server kantor, Anda sebagai lead developer akan menjalankan perintah ini untuk pertama kalinya agar tim lain bisa mulai melakukan pull.

2. Melihat Daftar Koneksi (git remote -v) +

Bagaimana jika Anda lupa ke mana kode Anda dikirim? Perintah ini akan menampilkan daftar URL yang terhubung.

git remote -v
🔍 Detail: Fetch vs Push URL

Biasanya keduanya sama. Namun, Git memungkinkan Anda mengambil (fetch) dari satu server dan mengirim (push) ke server lain untuk alasan keamanan tingkat tinggi.

3. Mengubah & Menghapus Remote +

Dalam dunia profesional, infrastruktur bisa berubah. Mungkin perusahaan pindah dari GitHub ke GitLab.

# Ganti URL karena pindah server
git remote set-url origin https://gitlab.com/user/proyek.git

# Ganti nama alias (dari origin ke pusat)
git remote rename origin pusat

# Putus hubungan dengan remote
git remote remove pusat
🏢 Kasus Real: Rebranding Proyek

Jika nama proyek berubah, URL git juga biasanya berubah. Alih-alih menghapus dan membuat folder baru, cukup gunakan set-url untuk menyambungkan ulang sejarah proyek Anda ke alamat baru.
