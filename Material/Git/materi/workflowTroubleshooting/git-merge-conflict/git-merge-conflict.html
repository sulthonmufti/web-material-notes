Merge Conflict

Seni Menyelesaikan Bentrokan Kode

1. Anatomi Sebuah Konflik +

Konflik terjadi ketika Git mencoba menggabungkan dua branch yang telah mengubah baris yang sama di file yang sama, atau satu branch menghapus file yang sedang diedit oleh branch lain.

📖 Istilah: Merge Aborted

Jika Anda merasa terlalu bingung di tengah jalan, Anda bisa membatalkan semuanya dan kembali ke keadaan sebelum merge dengan perintah: git merge --abort.

🏢 Kasus Real: Rebutan Style CSS

Si A mengubah warna tombol menjadi Merah di branch fitur-A. Si B mengubah tombol yang sama menjadi Biru di branch fitur-B. Saat keduanya digabung ke main, Git akan "angkat tangan" karena tidak tahu warna mana yang diinginkan klien.

2. Cara Git Menandai Konflik +

Saat terjadi konflik, Git akan mengotori file Anda dengan simbol-simbol aneh. Jangan dihapus sembarangan!

<<<<<<< HEAD (Perubahan Anda)
background: red;
=======
background: blue;
>>>>>>> fitur-B (Perubahan Teman)
🔍 Bedah Simbol:
  • <<<<<<<: Batas awal konflik (lokal Anda).
  • =======: Pembatas antara kode Anda dan kode mereka.
  • >>>>>>>: Batas akhir konflik (sumber remote/branch lain).
3. Workflow Penyelesaian (3 Langkah) +

Jangan panik, ikuti prosedur standar industri berikut:

  1. Buka File: Cari tanda <<<<<<<.
  2. Pilih: Hapus kode yang tidak diinginkan DAN hapus semua tanda Git (simbol-simbol tadi).
  3. Commit: Simpan hasil pilihan Anda.
# Setelah file diedit dan dirapikan:
git add .
git commit -m "fix: resolve merge conflict on background color"
4. Lab: Selesaikan Konflik Ini! +

Pilih kode yang ingin Anda simpan untuk menyelesaikan konflik:

<<<<<<< Current Change (Anda)
var name = "Sulthon";
=======
var name = "Mufti";
>>>>>>> Incoming Change (Rekan)
